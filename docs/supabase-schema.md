# Peramiho Bot — Supabase schema

The Supabase project for this repository is `peramiho-bot` in the TMB organization.

## Core tables

| Repository model | Supabase table | Notes |
|---|---|---|
| `database/models/User.js` | `public.users` | Passwords are stored as bcrypt hashes; API/reset tokens are represented by hashes. |
| `database/models/Session.js` | `public.sessions` | Stores session ownership, WhatsApp identity, connection state and counters. |
| `database/models/Setting.js` | `public.settings` | Stores global/per-session command and moderation settings. |
| `database/models/Ban.js` | `public.bans` | Stores session-scoped ban, mute and block records. |

## Security model

- RLS is enabled on every application table.
- No direct `anon` or `authenticated` policies/grants are created. The intended access path is a trusted server-side process using the Supabase `service_role` key.
- Never place the `service_role` key in browser code, public environment variables, GitHub, or a client-side bundle.
- The repository's Baileys auth credentials and key material (`creds` / `keys`) are intentionally excluded from Postgres. Keep them on an encrypted, persistent VPS volume with restrictive filesystem permissions and backups.
- `password_hash`, `api_token_hash`, and `reset_token_hash` must be generated by the server; never send plaintext passwords or bearer tokens to these hash columns.
- The database's `rls_auto_enable()` event-trigger helper is not a public RPC endpoint; execute permission has been revoked from `PUBLIC`, `anon`, and `authenticated`.

## Current integration status

The schema migration creates the database structure matching the repository's four model definitions. The current repository's `database/database.js` and `database/fileStore.js` still implement local JSON persistence. Applying this migration alone does **not** switch the running bot to Supabase. A separately reviewed server-side persistence adapter and data migration are required before changing the production runtime.

## Migration

Apply `supabase/migrations/20261121121700_create_peramiho_bot_core_schema.sql` to the target Supabase project. The migration is safe to re-run for existing objects and enables RLS on all four application tables.
